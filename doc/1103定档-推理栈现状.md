# 推理栈现状：精度 / 推理方式 / 加速 / 耗时 / 体积

> 测量机：i5-14600KF（6P+8E，AVX2，无 AVX-512），LLM 4 线程、解码 4~6 线程，Windows 11。
> 数字为热态（权重已进 cache）多次运行后的稳定值；冷启动另标。
> 代码位置：`csrc/src/{llm,gemv_avx2,attn_avx2,quant,sampler,decoder,audio_layer,encoder,engine}.cpp`。

## 1. 数据流

```
文本 ──SPM(int)──> prompt 行 [17 列 int32]
      ──global GPT-2 ×12 层──  W8A8, KV=fp32
          prefill：整段 prompt 批量算一次（169~181 行）
          step  ：每帧 1 次（喂上一帧 16 个 code）
      ──local 1 层 + 16 路 codebook 头──  W8A8
          每帧 17 次：1 次判「说完没」+ 16 次出 16 个 code
      ──采样器(fp32)──> codes[16][T]
      ──decoder──  fp16 权重 / fp32 激活与 KV
          chunk=8 流式，与 LLM 并行 ──> 48 kHz 立体声
```

## 2. 总表

| # | 环节 | 权重精度 | 激活 / 缓存精度 | 推理方式 | 加速手段（为什么） | 耗时 | 体积 |
|---|---|---|---|---|---|---|---|
| 1 | 文本前端 SPM | 无（trie + BPE 表） | int32 | 纯 CPU 串行 | 自实现 SentencePiece，零依赖；不做语义归一化（数字/单位原样喂模型） | < 1 ms / 句 | 0.43 MB |
| 2 | prompt 组装 | — | int32 | 模板拼接 | 与官方 `prompting.py` 逐 token 对齐（模板写错会多念 "None"） | < 0.1 ms | — |
| 3 | 音色前缀 KV | int8（Q8_0_4x4） | KV / hidden **fp32** | prefill 169~181 行，只算一次 | 前缀落盘 `.mosskv`，下次直接读；行指纹 + 权重指纹防错配 | 首次 **150~180 ms**；命中 **0.9 ms** | 9.1~18.5 MB / 音色 |
| 4 | global prefill（正文） | int8 + fp16 scale | 激活 int8（每行每 32 维动态量化）；LN/RoPE/GELU/attn **fp32** | 批量 GEMM（m = 行数） | 权重 12 层只读一遍（逐行 GEMV 要读 m 遍）；按 4 行组切给 4 线程 | **0.9 ms / 行**（16 token 正文 ≈ 22 ms） | 119.25 MB |
| 5 | global decode step | int8（**W8A16：激活不量化**） | 激活 **fp32**；KV cache **fp32** | GEMV（单行） | 4 行一组 repack（一次 load 覆盖 4 行、4 个 scale 相邻）；AVX2 maddubs；4 线程按行切 | **4.25 ms / 帧** | 同上 |
| 6 | local 头（1 层 ×17 + 16 个 codebook 头 + 词表头） | 同上 | 同上 | GEMV | 层权重仅 7.5 MB，常驻 L3，重复 17 次仍便宜；16 个声道头彼此独立 | **2.51 ms / 帧** | 含在 119 MB 内 |
| 7 | 采样器 | — | logits / 历史 **fp32** | rep-penalty → temp 0.8 → top-k 25 → top-p 0.95；结束判定走贪心 | 每通道去重历史、一次全排序；避免上游「每帧伯努利」提前收尾 | < 0.2 ms / 帧 | — |
| 8 | 解码器 | **fp16**（22.27 MB） | 激活 / KV **fp32** | chunk=8 分块流式，环形 KV 窗口 500/800/1200/1600 帧 | 与 LLM 流水线并行；窗口注意力只算最近若干帧；AVX2 + 多线程 | **5.9 ms / 帧**（67 帧 394 ms） | 22.27 MB |
| 9 | 编码器（仅克隆） | fp16 | 激活 fp32 | 整段卷积编码 | 只在建音色时跑 | 413 ms / 4.8 s 音频 | 21.76 MB |

**每帧合计**：global 4.25 + local 3.2 ≈ **7.4 ms**（LLM 段，W8A16）；解码器 5.9 ms/帧与之流水并行，端到端每帧 ≈ 6.5 ms。

## 3. 精度口径（唯一需要记住的一段）

- **量化只发生在矩阵乘的两个输入上**：
  - 权重 int8，每 32 个权重一组，`scale = fp16(amax/127)`；
  - 激活 int8，每行、每 32 维一组，运行时动态算 scale（逐行量化，不跨行共享）。
- 点积在 **int32** 里累积（k=768 最坏 127×127×768 ≈ 12.4 M，不溢出），再乘两个 scale 在 fp32 里累加。
- **其余全部 fp32**：LayerNorm、RoPE、GELU(erf)、softmax、残差、KV cache、logits、采样。KV 不做 fp16。
- `Q8_0_4x4` 与普通 `Q8_0` 的**量化值完全相同**，只改内存布局（4 行的 4 个 scale 相邻，一次 cache line 拿到 4 行）。
- 结论：**prefill 和 decode 是同一套 W8A8**，不是两种精度。

## 4. 已有精度实测

| 环节 | 指标 | 结果 |
|---|---|---|
| LLM W8A8 vs fp16 | teacher-forced code 翻转率 | **6.0%** |
| LLM W8A8 vs fp16 | logits KL / top-25 重叠 | **0.0009 / 97.4%** |
| 解码器 fp16 vs ONNX | SNR（带 context 窗口） | **61.1 dB** |
| 解码器 fp16 vs torch fp32 | SNR | 112 dB |
| 编码器 fp16（克隆） | 与 ONNX 编码器 codes 一致率 | 91.6~97.7%（帧数完全一致） |
| SPM | 与官方 sentencepiece | 61/61 逐 id 一致 |

自由生成（不 teacher forcing）的 codes 一致率不可用：argmax 对量化误差极敏感，一次翻转会级联。

上面 6.0% 是另一句的旧数据；同句 60 帧的 2×2 拆分（§7）里合计 10.0%，其中 decode 单独 8.2%、prefill 单独 2.7%。
即**同一套 W8A8 在不同句子上的翻转率在 6~10% 之间**，别把它当成固定常数。

## 7. prefill 与 decode 的精度拆分（2026-11-03 实测）

### 方法

给 `moss_llm` 加了 `--save-state / --load-state`（把 prefill 完的 **KV + 最后一行 hidden** 整份存盘，可跨权重精度移植），
就能把「prefill 的精度」和「decode 的精度」拆开：

| 组合 | prefill 权重 | decode 权重 | 含义 |
|---|---|---|---|
| A | f16 | f16 | 参考 |
| B | f16 | int8 | 只有 decode 误差 |
| C | int8 | f16 | 只有 prefill 误差 |
| D | int8 | int8 | 生产配置 |

四次运行喂**同一段 60 帧 codes**（由 f16 模型贪心生成，in-domain），逐帧比 logits 与 argmax。
注意必须用 in-domain 的 codes：拿别的句子的 codes 做 teacher forcing 会得到 88% 的假翻转，不能下结论。

### 结果

| 组合 | KL | top-25 重叠 | top-1 一致 | code 翻转 |
|---|---|---|---|---|
| B：仅 decode int8 | 0.003184 | 96.27% | 93.02% | **8.23%** |
| C：仅 prefill int8 | 0.000525 | 98.58% | 97.29% | **2.71%** |
| D：两者都 int8 | 0.004029 | 95.96% | 90.10% | **10.0%** |

### 结论

- **prefill 的 W8A8 不是主要来源**：KL 只有 decode 的 1/6，翻转率 1/3。
- 两者近似独立叠加：`A→B` 加的是 decode 误差，`A→D` 再加 prefill 误差，KL 从 0.00318 只涨到 0.00403。
- 精度损失的主体在 **decode 的逐 token 激活量化**：每帧 1 次 global + 17 次 local，每一步都重新量化激活，
  单 token 激活的分布比整段 prompt 更极端（少量 outlier 会把同块其它维度压扁）。
- prefill 一次算完、误差只在 KV 上落一次，反而更干净。

### 若要继续提精度（按性价比）

1. **激活改 fp16、权重仍 int8（W8A16）**：去掉激活量化误差，**每帧字节与带宽都不变**（激活只占 ~150 KB/帧，
   权重 90 MB/帧）。变的是每权重指令数：AVX2 没有 f16 算术，int8 权重得先展宽成 fp32 再 FMA，
   每 32 个权重从 ~4 条指令涨到 ~10 条。Q4 字节少 47% 却只快 20%，说明 Q8 下约一半时间不在等内存，
   余量不多 → 预计更慢，具体得写最小内核实测（未做）。
2. **激活 scale 改 min-MSE 搜索**（替代 `amax/127`）：预计算或每步搜几档，成本几乎为零，能吃掉一部分激活误差。
3. **LLM 直接 f16 权重**（224 MB、10 ms/帧、RTF 0.2）：作为听感基准，用来判断值不值得做 1、2。

## 8. 复现

```bash
# LLM 段（prefill + 每帧）
csrc\build\moss_llm.exe --weights weights\llm_q8x4.moss --prompt runs\promptfix\prompt_fixed.txt --frames 60 --greedy --threads 4
# 解码器（流式）
csrc\build\moss_decoder.exe --weights weights\decoder_f16.moss --codes runs\cpp\codes_q8x4_67.txt --out runs\precision\dec.f32 --stream 8 --threads 4
# 端到端
dist\moss-tts-cpu-win64\moss_tts.exe --models dist\moss-tts-cpu-win64\models --text "..." --voice Junhao --greedy --frames 60 --out runs\precision\a.wav
# 编码器（克隆）
csrc\build\moss_clone.exe --encoder weights\encoder_f16.moss --in ref.wav --out runs\precision\ref.mossclone
```
