## 2. 已经做了什么

### 2.1 推理（本轮之前已定档）

C++20 引擎，零第三方运行时依赖（只依赖 Windows 自带 DLL），权重 int8 `Q8_0_4x4`，
prefill 走 W8A8、decode 走 **W8A16**（发布默认），音频解码器 fp16 流式（chunk 8，首块 4 帧）。
精度：teacher forcing 下 code 翻转 5.2%、KL 0.00145（与 f16 参考，听感无差异）。Q4 已证伪，8 bit 是底线。

### 2.2 产品层（本轮新增）

| 模块 | 文件 | 职责 |
|---|---|---|
| Runtime | `csrc/src/runtime.cpp` | 单工作线程 + 有界队列(4) + job 表(TTL 10 min/32 条) + 取消 + 统计 + 音色枚举/克隆 + 路径解析 |
| HTTP 服务 | `csrc/src/server.cpp` | Winsock HTTP/1.1，只绑 127.0.0.1，`SO_EXCLUSIVEADDRUSE`，端口 8759→8763 顺延，Host/Origin 校验，CORS + PNA 预检，chunked PCM，静态文件，CSP |
| JSON | `csrc/src/json.cpp` | 最小解析器（深度 8、单串 8 MB、拒绝 NaN/Inf、支持代理对） |
| stdio 通道 | `csrc/src/stdio_server.cpp` | JSON 行协议：`speak`/`cancel`/`voices`/`clone`/`info`/`ping`，异步提交 |
| CLI 入口 | `csrc/src/tts_main.cpp` | 无参数 = 起服务并开浏览器；`--serve` / `--stdio` / `--port` / `--data` / `--allow-origin none` / `--version` |
| 试听台 | `web/app/{index.html,app.js,pcm-worklet.js}` | AudioWorklet 流式播放、停止、音色/克隆、保存 WAV、统计、离线引导 |
| 门户页 | `web/landing/index.html` | 性能数字、下载、三步、两段真实试听、"在网页里直接试听" |
| 插件 | `dsh-plugin/{index,backend,player}.mjs` | 4 个工具，spawn 常驻子进程，`System.Media.SoundPlayer` 播放 |
| 打包 | `scripts/{make_model_lock,fetch_weights,pack_release,release_check}.ps1` | 信任根、下载校验、三包产出、一键门禁 |
| 测试 | `tools/{http_smoke,stdio_smoke}.py`、`dsh-plugin/test-*.mjs` | 协议/取消/安全/跨源/插件 |

### 2.3 API（v1）

```
GET  /api/v1/health | /info | /voices
POST /api/v1/tts/stream      JSON -> chunked s16le / 48000 / 2ch（头 X-Moss-Request-Id、X-Moss-Audio-Format）
POST /api/v1/tts/wav         JSON -> 完整 WAV（可选 trim:true 裁尾）
POST /api/v1/voices/clone?name=<id>   body = WAV 字节
GET  /api/v1/jobs/{id}       统计：state/frames/audio_ms/compute_ms/first_pcm_ms/rtf/cache_hit
POST /api/v1/jobs/{id}/cancel
```

安全模型：只绑 loopback；Host 白名单挡 DNS rebinding；Origin 精确匹配（默认放行本机两个 origin +
项目门户 `https://litterbit.github.io`，`--allow-origin none` 可全关）；POST 强制 JSON/WAV Content-Type；
文本 ≤4000 字符、JSON ≤256 KB、上传 ≤20 MB。不使用 token（理由见 `doc/产品化与分发方案.md` §9）。

### 2.4 发布与门禁

- `scripts/model_lock.json` 是**已提交的信任根**（22 个文件的大小 + sha256）；打包前逐个校验。
- `pack_release.ps1` 产出 full/lite/sdk 三个**不带版本号**的资产名 → `releases/latest/download/<name>` 永久有效。
- `scripts/release_check.ps1` 一条命令复现整条门禁（11 步，顺序与 `release.yml` 一致）。
- `ci.yml` / `release.yml` / `pages.yml` 三条独立流水线。

## 7. 可能踩到的坑（产品层，详见 AGENTS.md）

1. **流式解码器跨请求泄漏** → 同一句话两次结果不同。已在 `synthesize` 入口 `reset_stream()`。
2. **无体 POST 被 400** → `/jobs/{id}/cancel` 没 Content-Length，早期版本直接拒；现在按 0 处理。
3. **PS 5.1 读无 BOM 的 UTF-8 `.ps1` 会解析坏** → 中文正文挪到 `doc/release_readme.txt`，
   `pack_release.ps1` 保持纯 ASCII；门禁里有编码守卫。
4. **`Compress-Archive` 用反斜杠存 zip 条目名** → 校验前先 `Replace('\','/')`。
5. **本机 `%TEMP%` / `%LOCALAPPDATA%` 在 DSH 沙箱里不可写** → 测试一律用仓库内 `runs/`。
6. **Chrome PNA 预检** 必须回 `Access-Control-Allow-Private-Network: true`；`ws://` 到 loopback 会被拦，
   所以协议只用 HTTP chunked。
