# MOSS-TTS CPU v0.1.2

音色克隆从"只能传 PCM WAV"变成"拖个 MP3 进来、在波形上选一段、试听、创建"；
顺手把默认音色、线程数和网页上的自助操作补上。

## 音色克隆：拖进来就能用

以前克隆只吃 PCM WAV，MP3 会报一句**跟真实原因无关**的错误：

```
克隆失败：WAV 块对齐不符合预期
```

根因是 `fmt` tag = 0x0055（MP3-in-WAV）时 `bits=0`，代码掉进了块对齐检查。现在：

- **网页上直接拖 MP3 / WAV / M4A / OGG / FLAC / WebM**——浏览器用 `decodeAudioData` 在本机解码，
  顺带把采样率转成 48 kHz。引擎保持零依赖，装不下 MP3 解码器，所以解码放在浏览器里；
- **波形上拖两端选片段**，两个滑块也能精调，`试听这一段` 只播选中的部分；
- **参考音频上限 20 秒**：长音频默认取前 20 秒，继续把终点往右拖，20 秒窗口整段滑过去；
- 创建时只上传选中的那段（重新打包成 PCM16 WAV），文件名自动变成音色名。

引擎侧的错误信息也改准了：

```
参考音频是 MP3 编码（0x0055），不是 PCM；请在网页里直接拖入音频（浏览器会解码），或先把文件转成 PCM WAV
参考音频最长 20 秒（这段 25.0 秒），请先裁剪
```

命令行同样能选段：`moss_clone.exe --in ref.wav --start 12 --seconds 8`（不给就取前 20 秒）。

## 默认音色：满满（manqu）

`manqu` 现在是内置音色，也是默认音色——网页、插件、curl 不传 `voice` 时都用它。
目录里没有这个音色时自动退到第一个内置音色，不会报错。

## 线程数：默认 2+3，网页上可改

两个独立线程池：`--threads`（LLM 出码）+ `--decode-threads`（音频解码器），流水线并行，
峰值占用 = 两者之和个核。默认从 4+6 降到 **2+3**（单核机器 1+1）：CPU 只忙 5 个核，安静不少；
速度大约慢 1.5 倍，想快就在面板里调回去（4+4 / 4+6）。

网页新增「性能」面板：直接填数字 → `保存` → `重启引擎`，页面自动刷新，不用自己去关窗口。
接口：`GET|POST /api/v1/settings`（返回**正在生效**的数字，不再显示 0+0）、`POST /api/v1/restart`。
线程数只影响速度与发热，**不影响音频内容**。

## 兼容性

- API 只加字段：`/voices` 多 `label` / `default`，新增 `/settings`、`/restart`；旧字段含义不变。
- 音色 id 没变（`Junhao`、`Xiaoyu` …）；`manqu` 从"用户音色"变成"内置音色"，
  如果之前克隆过同名音色，用户目录里那份可以删掉（内容一样）。
- `moss_tts.exe --voice` 不填时的默认值变为 `manqu`。
