# 音频质量问题排查记录

> 起点：试听网页反馈「**每段音频开头都不对，像多了一声“那/啊”，后面正确**」。
> 本文只记录**已经实测确认**的东西、**已排除**的方向、以及**还没验证**的假设，避免拍脑袋改模型。
> 时间：2026-11-01。机器：i5-14600KF（AVX2），4+6 线程，48 kHz 立体声。
> 权重：LLM `llm_q8x4.moss`（Q8_0_4x4）、解码器 `decoder_f16.moss`、音色 Junhao / taffy。

## 0. 一句话结论（当前认知）

**不是音色克隆的问题，也不是解码器/分词/prompt 模板的问题。**
两个现象都指向同一处：**这个模型在「帧 0」和「结束判定」这两点上，只有采样才勉强工作，而采样在这两点上都近似随机。**

- 帧 0 没有任何音频上下文 → 模型的分布最宽，采样会抽出一个**通用元音起音**（听感即多一声“那/啊”）；贪心取众数则是正确的辅音起音。
- 结束判定同样是「在 {slot, end} 两个候选上抽一次」→ 句长在 17~375 帧之间随机漂移；**贪心模式则永不停**。

## 1. 现象与量化

### 1.1 现象

| 现象 | 触发条件 | 听感 |
|---|---|---|
| 开头多一声“那/啊” | 采样（默认）；每段/每次生成都有 | 前 ~80–160 ms 是一个多余元音，之后正常 |
| 一句话说太长 / 停不下来 | 采样；与文本有关 | 说完后继续低声“念”到 10~30 s |
| 极短句也拖很长 | 采样 | 6 个字的句子出 12 s 音频 |

### 1.2 「开头多一声」的频谱证据

同一句「今天天气不错。」，同一音色，两张前 0.4 s 的 STFT（`runs/probe/onset_greedy_vs_sample.png`，
上=贪心，下=采样）：

- **贪心**：最左端是一道**窄而高的宽带竖条**（能量铺到 3 kHz 以上）→ 辅音起音（“今”的 j-），随后进入元音。
- **采样**：最左端是**一大团平滑的低频元音**（无辅音起音、宽带能量缺失）→ 多出来的那个“啊/那”。

### 1.3 codes 层面的证据

同一句、同一音色、同一个 prompt（180 行），只换采样方式（`moss_llm --prompt runs/probe/p_short.txt`）：

| 帧 | 贪心（= ONNX 官方贪心） | 采样 seed 0 | 说明 |
|---|---|---|---|
| 帧 0 | `653 256 410 336 12 882 750 441 …` | `653 102 984 325 269 155 333 700 …` | **只有第 0 个通道相同**，平均绝对差 **276** |
| 帧 1 | `125 860 949 551 751 …` | （不同） | 帧 0 一歪，后面全歪 |

也就是说：**帧 0 的码在采样下几乎是随机抽的**，而贪心抽到的正是 ONNX 官方那一个。

## 2. 关键实测：我们 vs ONNX（同一 prompt、同一权重、同一音色）

| 实验 | 我们的引擎 | ONNX 官方运行时 | 结论 |
|---|---|---|---|
| 贪心，帧 0 codes | 与 ONNX **16/16 逐位相同** | 同左 | prompt/分词/模板/LLM 数值通路**完全一致** |
| 贪心，帧 1–2 codes | 每帧只差 1~2 个通道 | — | 已知的 int8 量化噪声（teacher-forced 翻转 6%），非结构错误 |
| 「今天天气不错。」贪心 | 17 帧（与 ONNX 相同） | 17 帧 = 1.36 s | 贪心能正常收尾 |
| 「你好…基准测试音频。」贪心 | 不停（跑到帧上限） | **375 帧（30 s）也不停** | 贪心模式下**双方都停不下来** |
| 「你好，这是克隆音色的测试…」贪心 | 不停 | **375 帧（30 s）** | 同上 |
| 同一句 ONNX 采样（fixed） | — | 67 帧 / 21 帧 | 采样能停，但停在哪很随机 |
| 同一句我们采样 | 64 帧（基准句）/ 152 帧（短句） | — | 与 ONNX 采样量级接近但不可复现 |
| 克隆参考（taffy）+ 贪心 | 不停 | **375 帧** | **克隆不是原因**，官方同样表现 |

结论：
1. **数值通路是对的**（帧 0 逐位一致、解码器 61.14 dB、流式=整段逐位相同）。
2. **「开头多一声」= 帧 0 被采样歪了**，贪心不会。
3. **「说太长/停不下来」= 结束判定只有采样时才可能触发**：贪心永不触发（双方一致），采样则随机距离很远（21~375 帧）。

## 3. 已排除的方向（都做过对照）

| 方向 | 排除依据 |
|---|---|
| 音色克隆/编码器 | ONNX 官方用同一段参考音频（`taffy_pcm.wav`）跑，帧数与行为和我们一致；且克隆档案的 codes 回放 SNR 6.03 dB ≈ ONNX 6.01 dB |
| 解码器 | 整段对 ONNX **61.14 dB**；流式与整段**逐位相同（maxdiff 0.0）**；WASM/量化都不是变量 |
| 分词器 / prompt 模板 | 61/61 句与官方 sentencepiece 逐 id 一致；prompt 行数、模板 id 与 manifest 对拍一致；帧 0 codes 与 ONNX 逐位相同 |
| 采样参数抄错 | 与 manifest 的 `generation_defaults` 一致（0.8 / 25 / 0.95 / 1.2）；改贪心后行为与 ONNX 贪心一致 |
| 分块/流式拼接 | 分块解码与整段解码逐位相同（因此段与段之间不存在数值接缝） |
| 网页层 | 网页只是调 CLI；用 Python 客户端复测同样现象（早期的 25 token 是我 PowerShell 传参把 UTF-8 打碎，已排除） |

## 4. 根因分析

### 4.1 帧 0 为什么必然脆弱

生成第 0 帧时，模型只有 prompt（模板 + 参考音频 + 正文），**没有任何自回归的音频上下文**。
这一帧的音频头分布最宽（说话人、语速、起音都还没确定），所以：

- **贪心**：取众数 → 稳定落在正确辅音起音上（与 ONNX 官方一致）。
- **采样**（温度 0.8 / top-k 25 / top-p 0.95）：从宽分布里抽一次 → 很容易抽成一个“万能元音”，
  听感即多一个字；而且这个错误会作为后续帧的上下文传下去（帧 1 起就跟着歪）。

### 4.2 结束判定本来就只是「一次伯努利抽样」

上游 `_sample_assistant_text_token` 的候选集只有两个 token：`audio_assistant_slot(9)` / `audio_end(7)`，
按 softmax 概率抽一个。所以「说完了」不是模型给出的确定信号，而是**每帧抽一次**：

- 贪心（`end > slot` 才停）：实测 400 帧内 `logit[9]-logit[7]` 一直保持 **+10~+14**，永不下穿 → 永不停；
- 采样：某帧抽到 end 就停 —— 停在第几帧取决于随机数，实测同句在 **17 / 21 / 64 / 152 / 375 帧**之间都出现过。

> 也就是说：**“开头多一声”和“说太长”是同一个设计缺陷的两面** —— 该模型把「起音」和「结束」都交给了采样。

## 5. 还没验证 / 存疑的点

1. **裸 `▁` token 是否有份**：`今天天气不错。` 的分词是 `[▁][天气][不错][。]`，第一个是**单独的 `▁`**
   （不是 `▁今`）。它可能被模型当作一个“词边界”甚至一个音节来念。尚未做「去掉裸 `▁` 再生成」的对照。
2. **前 N 帧贪心是否足够**：已实现 `greedy_frames`（默认 1），验证了帧 0 的 codes 会变成贪心值，
   但**还没试听确认**“多一声”是否消失，也没确认 1 帧够不够（也许是 2 帧）。
3. **克隆音色的起音是否同样受帧 0 采样影响**：按机制应当一样，但没单独试听确认。
4. **贪心模式永不停**：需要产品层面的兜底（按时长/字长设上限），否则 `--greedy` 不可用。
5. **采样下的句长分布**：目前只有零散样本（17~375 帧），没有统计意义上的分布，
   也就无法判断「152 帧」是离群还是常态。

## 6. 修复方向（按侵入性排序）

| 方案 | 做法 | 影响 | 现状 |
|---|---|---|---|
| **A. 前 N 帧贪心** | `SampleParams::greedy_frames`，生成前 N 帧用 argmax，之后恢复采样 | 只改采样，不动模型；起音稳定为“众数” | **已实现（N=1）**，待试听确认 |
| **B. 时长兜底** | 按 token 数估上限（如 3.0×tokens + 16 帧），超过即停 | 只防“说太长”，可能截断慢速句 | 未实现 |
| **C. 结束判定改进** | 例如要求 `p(end)` 连续 K 帧超过阈值，或用校准过的 logit 差阈值 | 需要数据集校准，风险较高 | 未实现 |
| **D. 去掉开头裸 `▁`** | 分词后丢弃首个纯 `▁` 的 id | 只影响首 token；需先验证它是否真的被念出来 | 未验证 |

验收口径（建议）：
- A：同一句、同一 seed，帧 0 codes 与贪心逐位一致（已可自动检查）；试听无多余起音。
- B：20 句语料下“最长句长 / 字”不超过阈值，且不截断正常句（人工试听）。
- C：需要建立 20~50 句的“自然句长”参考集（例如用 ONNX 官方采样多 seed 取众数），成本较高。

## 8. 结论备忘

- 送修的**不是**克隆、解码器、分词或模板；**是模型在「首帧」与「结束」两处只依赖采样**。
- 我们的数值实现与官方一致（帧 0 逐位相同、解码 61 dB、流式=整段），所以**没必要重训或改权重**。
- 可用工程手段把这两点“按住”：首帧贪心（A）+ 时长兜底（B）。这两条都不改模型结构。
- 裸 `▁`（第 5.1 条）值得单独试一次，成本很低。
