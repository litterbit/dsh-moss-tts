# LLM 优化：目标规格与实施计划（v2，已按用户确认收敛）

> **执行结果（2026-11-03）**：敏感度扫描已完成（39 组 × 2 语料），数据与结论见 `doc/LLM精度实验记录.md`。
> 关键结论：**Q4 不可用**（flip 8.7% → 60~86%），"降精度换速度"在本模型上不成立；
> 已交付两项零损失优化（首音 112 → **50 ms**、判句末只算 2 行）。
> 两档现状：**档① 可行并已交付；档② 在精度轴上无可用手段**（需 Q6 内核或解码器优化）。

> 2026-11-03 v2。相比 v1：只做两档、首音优先、包体不限、本轮不动内核、只走精度轴。
> 现状账本见 `doc/推理栈现状.md`；两段精度拆分见其 §7。

# A. 目标规格

## A0. 适用范围

- **通用 Windows x64**：不针对某颗 CPU 调参。**AVX2 是唯一硬门槛**（2013 年后 x86 全部具备），
  没有 AVX2 走标量路径且必须仍能实时。AVX-512 / AVX-VNNI 只作"有则加速"。
- Windows on ARM64 本阶段不做，但 kernel 层留 NEON 接口位。

## A1. 设备自校准（只看能力，不看型号）

加载后跑 ~30 ms 微基准，测 `bw_eff`（GB/s）、`mac_rate`（GMAC/s）、核数、ISA，据此选默认档与线程数：

| 类 | 判定 | 默认档 |
|---|---|---|
| A | `bw_eff ≥ 20 GB/s` 且 ≥4 核 且 AVX2 | 档① |
| B | `bw_eff 10~20 GB/s` 且 ≥2 核 | 档① |
| C | `bw_eff < 10 GB/s` 或 无 AVX2 或 仅 2 线程 | 档② |

## A2. 速度目标

**A 类每帧速度不再是硬指标**（已经很快），重点转向**首音**：

| 指标 | 现状 | 目标 |
|---|---|---|
| 首音（音色前缀命中） | 117~128 ms | **≤ 80 ms** |
| 首音（冷缓存，换音色第一次） | 269 ms | ≤ 150 ms（后台预热前缀） |
| A 类每帧（LLM） | 6.5 ms | 不作为约束（4 ms 上下即可） |
| 档② 端到端 | — | 见下 |

档② 的"尽可能快"以**听感可接受**为界（用户人耳验收），客观下限：

| 场景 | 目标 |
|---|---|
| 弱机（2 线程） | RTF ≤ 0.80，不欠载 |
| 强机（4 线程） | 每帧 ≤ 2.5 ms、RSS ≤ 150 MB |

## A3. 资源目标

| 指标 | 现状 | 档① | 档② |
|---|---|---|---|
| 峰值 RSS | 249 MB | ≤ 200 MB | ≤ 150 MB |
| 稳态 CPU 占用（A 类） | ~8% 单核 | ≤ 5% | ≤ 3% |
| 空闲行为 | 无线程 | 零轮询、below-normal 优先级 | 同左 |
| 包体 | 170.8 MB | 不限（两档各带一份权重） | 不限 |

## A4. 两个精度档（唯一的分档，不再按设备分三档）

参考基线固定为 **f16 全精度**。当前生产（Q8）≈ 档① 的现状水平。

| 档 | 定位 | 精度要求 | 备注 |
|---|---|---|---|
| **①** | 精度基本不掉、更快 | **不劣于当前生产**（ΔKL ≤ 0.004、Δflip ≤ 10 pp vs f16）；允许比现在略差一点点 | 必须过听感 A/B |
| **②** | 精度降到可接受、尽量快、省资源 | 听感可接受即可（用户人耳验收），客观只记录不设死线 | 允许全局 Q4 + KV 降位 |

- 统计口径：in-domain teacher forcing，3~4 句 × 60~150 帧，翻转率二项 σ ≈ 0.56 pp（每句 60 帧）。
- 每条候选同时报 `ΔKL`、`Δflip`、`top-25 重叠`。
- **听感验收**：用较长的测试音频（≥10 s）并包含**音色克隆**；候选组合各做一次 A/B。

## A5. 本轮范围（用户确认）

- **只做精度轴**：权重位宽（Q8/Q4）、激活与 KV 的位宽/格式。不做 KV 窗口截断、跳层、结构近似。
- **不动内核**：Q4 解包、AVX-VNNI 分派都留到后续（见 D 节）。本轮 Q4 的速度收益按现有内核实测，不假设。
- 允许做**精确的**工程优化（不改变任何数值），例如词表头只算需要的 2 行 —— 这不属于"结构近似"。

# B. 执行计划

## B0. 账本（Q8 生产，上下文 245 位）

| 组成 | 字节/帧 | 占比 | 实测时间 |
|---|---|---|---|
| local 层权重 ×17 次 | 127.8 MB | 48% | 2.51 ms（L3 命中） |
| global 12 层权重 | 90.2 MB | 34% | 3.96 ms |
| global KV 读取 | 18.1 MB | 7% | 含上行 |
| 16 个 codebook 头 | 13.4 MB | 5% | 含 local |
| 词表头（只判句末） | 13.4 MB | 5% | 含 local |
| **合计** | **263 MB** | | **6.47 ms** |

## B1. 首音链路（用户重点）

首音 117 ms = 正文 prefill 22 ms + 首块 8 帧 × 6.5 ms + 解码器首块 37 ms。

| 项 | 做法 | 预期 | 代价 |
|---|---|---|---|
| 1a 首块减半 | `chunk_frames` 首块用 4 帧，稳定后回到 8 | -26 ms | 块开销 +2 ms/块 |
| 1b 前缀后台预热 | 换音色时异步算 `.mosskv`，不占首音预算 | 冷启动 269 → ~120 ms | 需要一个后台线程 |
| 1c prefill 与首块重叠 | prefill 就把首行的 hidden 传给 local，先出第 0 帧 | -10~15 ms | 改流水线，风险中 |
| 1d 解码器提前启动 | 首块一凑齐立刻解码，不等整块 | -10 ms | 已有流水线，微调 |

## B2. 敏感度图谱（本轮核心，先做）

目的：回答"哪些区域降精度几乎不掉质量"，并给出每单位精度损失换到的资源。

装置（全部现成）：

- 权重导出：`tools/export_weights.py --plan-file`（JSON override，逐张量组指定 dtype）。
- 参考：`llm_f16.moss`；对照：`llm_q8x4.moss`（当前生产）。
- 分离 prefill / decode：`moss_llm --save-state / --load-state --ignore-state-fp`。
- 语料（4 组，含克隆与长音频）：
  1. `zh_mid`：中文短句（约 60 帧）
  2. `zh_long`：中文长句（≥150 帧，约 12 s）
  3. `en`：英文（约 50 帧）
  4. `clone`：克隆音色（`deepseek_letmogo`，约 60 帧）

扫描组（39 个）：

| 组 | 张量 | Q8 字节/帧 |
|---|---|---|
| G0..G11 | 每层 `attn.w` | 1.88 MB |
| P0..P11 | 每层 `proj.w` | 0.63 MB |
| F0..F11 | 每层 `fc_in+fc_out` | 5.01 MB |
| L | `local.*`（4 个矩阵，×17 次） | 127.8 MB |
| E-aemb | `aemb.*`（16 个） | 13.4 MB |
| E-wte | `wte` | 13.4 MB |

每个组跑三种配置（同一段 in-domain codes）：

1. **只降 decode**：Q8 prefill 状态 + 该组 Q4 的 decode
2. **只降 prefill**：该组 Q4 的 prefill + Q8 decode
3. 参考：f16 全精度、Q8 生产

指标：`ΔKL`（vs f16 logits，temp 0.8）、`Δflip`、`top-25`，以及该组省下的字节/帧。
得分：

```
A   = max(ΔKL / 0.004, Δflip_pp / 10)     # 归一化到"当前生产的全部损失" = 1.0
S_B = 节省字节% / max(A, 0.01)            # 每单位精度损失的带宽收益（∞ 表示无损）
```

分两轮：先在 `zh_mid` + `zh_long` 上筛 39 组；再在 4 组语料上复核前 10 名。

## B3. 组合与两档定稿

- **档①**：只收 `A ≤ 0.25`（近乎无损）的组 + 精确优化（词表头 2 行、KV fp16 若 ΔKL 达标）。
- **档②**：全局 Q4（除 aemb 若敏感则保留 Q8）+ KV fp16 + 精确优化，实测速度与听感。
- 输出：`tools/export_weights.py` 内置 `t1` / `t2` 两个 plan（带注释），两档各生成一份权重。
- 听感：档①/档② 各出 12 s 长音频（含克隆音色）与 f16 参考做 A/B，用户拍板。

## B4. 验收

- 客观：4 组语料的 ΔKL/Δflip 表；每帧字节、每帧 ms、RSS、首音。
- 主观：≥12 s 长音频 + 克隆音色，三份（f16 / 档① / 档②）。
- 回归：`tools/check_torch_frame0.py`、三句验收音频、web 端冒烟。

# C. 已确认的决策（不留待讨论）

1. 两档，不按设备分三档；设备自校准只决定默认跑哪档。
2. 档① 允许比当前生产略差一点点；档② 以听感为准，客观不设死线。
3. 首音目标 80 ms（热）/150 ms（冷）。
4. 包体无限制：两档各带一份权重文件。
5. 本轮不做结构近似、不动内核。
6. 敏感度先出表，再按实际效果搭配。

# D. 后续（本轮不做，已记录）

- **内核**：Q4 现在只快 5%（解包开销吃掉带宽收益），要让档②真正快到 2 倍必须重写 nibble 内核。
  参考实现：llama.cpp 的 `ggml_vec_dot_q4_0_q8_0`（AVX2：16 字节半块 `maddubs`+`madd`，
  以及 `__AVXVNNI__` / `__AVX512VNNI__` 分支的 `vpdpbusd`）。我们已有 4×4 repack，
  剩余差距主要在寄存器压力与预取，可以照抄它们的循环结构。
- 结构近似：KV 窗口截断、跨通道权重共享。
- ARM64 NEON 路径。
